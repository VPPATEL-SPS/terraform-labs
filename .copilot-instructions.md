# Copilot Instructions for Terraform Labs

This repository contains example Terraform code and labs for learning infrastructure as code practices. When assisting with this repository, please follow these guidelines:

## Terraform Development Principles

### Code Organization
- Use descriptive resource names that indicate their purpose
- Group related resources in logical modules
- Maintain consistent file naming: `main.tf`, `variables.tf`, `outputs.tf`, `versions.tf`
- Use subdirectories for different environments or modules

### Naming Conventions
- Use lowercase with underscores for resource names
- Prefix resources with their type or environment when appropriate
- Example: `web_server_instance`, `db_security_group`, `prod_vpc`

### Variable Management
- Define all variables in `variables.tf` with descriptions
- Use appropriate variable types (string, number, bool, list, map)
- Set sensible defaults where applicable
- Group related variables together

### Security Best Practices
- Never hardcode sensitive values in Terraform files
- Use Terraform variables for environment-specific values
- Implement least privilege access policies
- Use data sources for existing resources when possible
- Comment security-related configurations clearly

## Code Quality Standards

### File Structure
```
terraform-lab/
├── main.tf              # Primary resource definitions
├── variables.tf         # Input variable declarations
├── outputs.tf          # Output value declarations
├── versions.tf         # Provider version constraints
├── terraform.tfvars.example  # Example variable values
└── README.md           # Module documentation
```

### Documentation Requirements
- Include clear descriptions for all variables and outputs
- Provide usage examples in README files
- Document any prerequisites or dependencies
- Explain the purpose and scope of each module

### Testing Approach
- Always run `terraform validate` before committing
- Use `terraform plan` to review changes
- Include example `.tfvars` files for testing
- Document expected infrastructure outcomes

## Common Patterns

### Provider Configuration
```hcl
terraform {
  required_version = ">= 1.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
}
```

### Resource Definitions
```hcl
resource "aws_instance" "web_server" {
  ami           = var.ami_id
  instance_type = var.instance_type
  
  tags = {
    Name        = var.instance_name
    Environment = var.environment
    Project     = "terraform-labs"
  }
}
```

### Variable Definitions
```hcl
variable "instance_type" {
  description = "EC2 instance type for the web server"
  type        = string
  default     = "t3.micro"
  
  validation {
    condition     = contains(["t3.micro", "t3.small", "t3.medium"], var.instance_type)
    error_message = "Instance type must be t3.micro, t3.small, or t3.medium."
  }
}
```

## Learning Lab Guidelines

### Example Structure
- Each lab should focus on a specific Terraform concept
- Include step-by-step instructions in README
- Provide both beginner and advanced examples
- Include common troubleshooting tips

### Educational Focus
- Explain the "why" behind configuration choices
- Show both correct and incorrect examples when helpful
- Include links to official Terraform documentation
- Demonstrate real-world use cases

## Error Handling and Debugging

### Common Issues
- Suggest checking provider authentication when resources fail
- Remind to run `terraform init` after adding new providers
- Encourage using `terraform plan` before applying changes
- Suggest checking for resource naming conflicts

### Best Practices for Labs
- Include cleanup instructions (`terraform destroy`)
- Warn about potential costs for cloud resources
- Provide alternative configurations for different cloud providers
- Include estimated completion times for labs
